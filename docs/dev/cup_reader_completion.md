# 終了大会の定期取得停止

`scripts/call_update_csv.sh` は日次更新時に、天皇杯2026とルヴァンカップ26-27が終了したかを取得済みCSVから判定する。大会が終了していれば、その大会のreaderを省略する。ルヴァンは元データ取得と公開CSVへの変換を両方省略する。他大会の更新は継続する。

## 終了条件

`config/competition_completion.yaml` に、対象CSV・大会全体の想定試合数・決勝の正式ラウンド名を設定する。

| 大会 | 想定試合数 | 決勝ラベル |
| --- | --- | --- |
| 天皇杯2026 | 87 | `決勝戦` |
| ルヴァンカップ26-27 | 65 | `決勝` |

次をすべて満たす場合だけ、取得を停止する。

- 想定試合数と一致し、試合番号・同一ラウンド内のカードに重複がない
- 完全一致する決勝ラウンドが含まれる (`準決勝` を決勝と判定しない)
- 全試合の対戦チームが具体化し、状態が `試合終了`、両チームの得点が有効
- 一発勝負で同点の場合は有効なPK結果がある。H&Aの各レグの引き分けは許容するが、同じラウンド・2クラブの第1戦と第2戦が揃い、ホーム・アウェイが反転していることを確認する
- 全試合の日時が確定し、JSTで実行時刻を過ぎている

現在配信されている行がすべて終了していても、後続ラウンドが未配信なら停止しない。例えば、ルヴァンの準々決勝までの60試合が終了しても、65試合に達するまでは取得を続ける。固定の終了日や `section_no=-1` だけでは停止しない。

## 運用

終了判定は、その回の取得前に行う。決勝結果を取得してCSVを更新した後、次の日次更新から省略する。スキップ理由や継続理由はGitHub Actionsのjob summaryに表示する。

CSVがない、壊れている、日時が未定、未来の試合がある、中止・延期・速報などの場合は、修復や結果確定のため取得を続ける。設定ファイルや判定プログラムに異常があれば、readerは引き続き実行し、取得済み変更のコミットを妨げず、ジョブを失敗として報告する。

GitHub Actionsの手動実行 (`workflow_dispatch`) は終了判定を省略し、全readerを再取得する。終了後に公式結果が訂正された場合も、手動実行で反映できる。

次シーズンのreaderへ切り替える際は、対応するCSVパス・想定試合数・決勝ラベルも更新する。これらは大会方式から定め、現在配信されている行数で置き換えない。

## 判定だけを確認する

リポジトリ直下で実行する。ネットワーク取得は行わない。

```bash
uv run python scripts/competition_completion.py EmperorsCup
uv run python scripts/competition_completion.py JLeagueCup
```

終了コードは `0` が終了確認済み、`1` が継続、`2` が設定・判定処理の異常。テスト用には `--config PATH` と `--now ISO_DATETIME` を指定できる。タイムゾーンのない日時はJSTとして扱う。
